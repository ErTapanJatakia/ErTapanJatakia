# Project Roadmap

**Planning period:** 2026-11-25 to 2027-11-24  
**Owner:** Repository owner  
**Status:** Maintained planning baseline; priorities may be reordered through documented project decisions.

## Purpose and scope

This project maintains a public professional profile and the supporting repository content, documentation, repository configuration, Ruby validation utilities, and GitHub Actions automation. The roadmap covers those deliverables. It does not promise an end-user application, hosted service, commercial product, compiled binary, or application API.

The project prioritizes accurate professional information, accessible and maintainable presentation, secure repository operations, verifiable documentation releases, and transparent security evidence.

## Ongoing commitments

- Keep profile claims, credentials, dates, links and public contact information accurate; owner approval is required for changes to personal claims.
- Review broken links, embedded assets and accessibility defects when reported and during the scheduled content review.
- Run repository validation on pull requests and pushes to the default branch; preserve required checks and do not weaken tests to obtain a green result.
- Keep GitHub Actions pinned to full commit SHAs and review dependency updates, permissions and licenses before accepting material changes.
- Review security policies, threat model, external interfaces, VEX records and release-verification instructions after material changes and at least annually.
- Keep vulnerability reports private and follow the response commitments in SECURITY.md.
- Publish documentation/source-configuration releases only through the documented controlled release process.
- Reassess the roadmap at least quarterly and record material changes through a pull request.

## Explicitly out of scope for this planning period

- Building or operating an end-user software application, public API, database-backed service or production infrastructure.
- Publishing compiled application binaries or claiming application-level runtime coverage.
- Introducing paid services, paid APIs, telemetry, tracking scripts or new third-party services without explicit owner approval.
- Claiming independent security certification, an awarded OpenSSF badge, or a human review that did not occur.
- Treating automated checks as a substitute for independent human review or maintainer continuity.

## Governance and changes

The repository owner approves roadmap changes. Contributors may propose changes through issues and pull requests. Accepted changes must preserve the scope boundaries above unless the owner explicitly approves a project-scope change. Material changes to security, release, dependency, credential or governance commitments require the relevant policy and assessment documents to be updated in the same change.
