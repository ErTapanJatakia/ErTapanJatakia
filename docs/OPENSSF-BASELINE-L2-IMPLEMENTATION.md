## Evidence and scope guardrails

- This is the official **Baseline Level 2** control set (19 controls), not the OpenSSF Passing/Silver/Gold badge series.
- The official criteria version used is `v2026.08.28`; reassess if OpenSSF changes the criteria.
- The repository is documentation/profile content plus GitHub Actions automation. Documentation-release evidence must not be misrepresented as a compiled software build, application interface or runtime.
- A GPG signature does not satisfy DCO/CLA legal authorization. The legal sign-off control remains Unmet.
- The current main ruleset has seven required checks and no bypass actors. The separate VEX regression test job is not a required check for every ordinary PR; QA-06.01 therefore remains Partial.
- The security policy currently has no response SLA; VM-01.01 remains Unmet until a realistic response timeframe is published and operationally supportable.
- The access governance policy and owner-confirmed collaborator review do not constitute a complete member-to-sensitive-resource inventory.
- The connected GitHub integration cannot verify the account-level MFA setting, Actions default token permissions, Private Vulnerability Reporting toggle, or full collaborator/team roster. These are not inferred from repository documents.
- The owner-reported clean vulnerability/malware view is time-bound and must not be converted into a perpetual assertion of zero vulnerabilities.

## Reassessment triggers

Reassess when platform settings become independently verifiable, the member/access inventory is completed, a DCO/CLA enforcement mechanism is introduced, QA tests become required for every PR, a realistic vulnerability-response timeframe is adopted, private reporting is confirmed enabled, a vulnerability is discovered, or software build/runtime/API assets are introduced.
